# Preparação real das identidades QA V2 (desativadas)

O script `scripts/guardian_qa_prepare_disabled_identities.py` usa apenas o gcloud autenticado do responsável. Projeto e número fixos, billing desativado obrigatório. Por padrão faz leitura de metadados e salva cópia privada das Rules QA atuais no Debian. Com `--apply 'PREPARAR QA V2 DESATIVADO'` cria somente duas contas Firebase Auth sem senha/email/provedor e desativadas, UIDs fixture_triage e fixture_activation, com claims guardianQaRole correspondentes. Não sobrescreve contas existentes divergentes. Em falha parcial não habilita nem apaga contas; exige revisão. Não cria IAM, chaves, secrets, tokens de usuário, documentos Firestore ou novas APIs, nem publica regras. Se API não disponível, não habilitar automaticamente.

A publicação depende de revisão das Rules reais: matches sobrepostos têm semântica OR. É necessário impedir que regras legadas concedam acesso aos novos UIDs fora do namespace, proteger também o namespace de outras identidades e testar a composição no emulador. Não substituir a política QA existente pela política demo. O snapshot privado não deve ser enviado a repositório público. Sem deploy, login dos novos usuários ou ativação antes da revisão. WIF leitor e produção preservados. Status NO_GO_ESCRITA até prova real com Firebase ID tokens. Testes unitários de provisionamento usam exclusivamente respostas simuladas.
