# Push Automático 1.0 — etapa 03A: autenticação em laboratório

Contrato isolado para a futura entrada de serviço, não importado pelo gerador do Worker. Desligado por padrão. Assinatura RS256 efetivamente verificada com Web Crypto e chave RSA pública resolvida por kid; os testes geram chaves descartáveis localmente. Não há credencial Google real, consulta JWKS, endpoint montado, FCM ou alteração de infraestrutura. A identidade email/sub é configuração do servidor QA, ainda não provisionada. O token só pode carregar a identidade; o corpo aceita exclusivamente eventKey, sem destinatário, texto ou token FCM. Autenticação não autoriza envio. Validade nominal <= 1h e idade de emissão <= 5 min são decisões candidatas; confirmar compatibilidade do emissor real. Audiência exclusiva proposta.

Referência: documentação oficial Google Cloud sobre ID tokens de contas de serviço e OpenID Connect (https://docs.cloud.google.com/docs/authentication/token-types e https://developers.google.com/identity/openid-connect/openid-connect). Antes de qualquer rota: resolver JWKS oficial fixo com cache e rotação, revisão independente, validar token real em ambiente isolado, limitar requisições e tamanho no handler, autenticar runtime, ler outbox canônico e adquirir claim transacional, revalidar todas as autorizações no Worker e usar reserva D1 já existente. Repetição de bearer é possível durante validade; não confundir verificação de assinatura com proteção contra replay. Não reenviar automaticamente quando resposta FCM é ambígua. Não houve concessão IAM, configuração, deploy ou alteração de /event ou /notice.
