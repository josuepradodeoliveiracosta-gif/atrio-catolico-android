# Push Automático 1.0 — 05G2: claim e finalização REST

Adaptador privado de laboratório com beginTransaction, leitura exata do outbox, revalidação do snapshot na mesma transação, vínculo de versões, criação, recibo, pendência, gerações, autorização e janela original; commit com máscara e precondição updateTime. Reserva exclusiva com UUID e timestamp servidor; resultado de commit ambíguo nunca autoriza envio. Finalização valida UUID e estado, resultado após vencimento vira unknown; expiração de claim não libera nova tentativa. Usa a reserva de transporte externa já existente; chamadas diretas nos testes são fixtures, não interface de produção. Integração com Worker gerado passa a usar claim/finish REST no teste de fluxo, em vez de SDK. Corrida REST/SDK, revogação, UUID errado, perda simulada de resposta após commit e expiração cobertos por testes. CI precisa validar. Ainda usa SDK para leitura pós-claim no harness, Auth emulado e FCM sintético. Não há prova de orçamento integral, CPU Free, IAM efetivo, coalescência/retry REST ou scheduler. Não há ativação remota, faturamento, mudança IAM, main ou APK.
